# 反人类设计原则 · Design Principles

> 「反人类」不是乱来。
> 一个让人抓狂的页面，和一堆随机乱跳的 `alert`，区别在于**前者有一份设计文档**。

本文档说明 Anti-Human Tests 系列中每一处「恶意」背后的设计意图。
如果你要贡献新页面，请先读完这一页。

---

## 一、总纲

本项目测试的不是用户的知识，而是**用户在受挫时的行为模式**。

因此我们遵守一条铁律：

> **每一个让人抓狂的设计，都必须能被一句话解释清楚它想测试什么。**

说不出来的，就是没设计，直接删掉。

---

## 二、七种「反人类」手法

### 1. 栈顶诱饵（Stack-Top Decoy）

**机制**：把无辜的组件放在最显眼的位置，把真凶埋在 `Caused by` 的最深处。

**为什么有效**：人类阅读日志是**自上而下**的，而程序的错误是**自内向外**传播的。
这个错位是所有崩溃排查痛苦的根源。

**应用**：[反套路版](../mc-crash/evil.html) 全篇。

> 经典案例：`UnsupportedClassVersionError` 的栈顶是某个模组，
> 但真正的解决方案是**升级 Java**，不是骂模组作者。

---

### 2. 正确但无用（Technically True, Practically Useless）

**机制**：给出的信息全部正确，但**不足以定位问题**。

**为什么有效**：让人产生「我明明看懂了」的错觉，然后在下一步彻底迷路。

**应用**：日志里出现 `... 38 more`——中间栈帧被省略，
任何声称「完整还原了调用链」的人都在编故事。

> 正确的态度是承认：**直接肇事者可定位，完整链路无法还原。**

---

### 3. 误导性熟悉感（Misleading Familiarity）

**机制**：抛出一个用户很熟悉、因而**不会怀疑**的答案。

**为什么有效**：经验在这里成为负资产。越是老手越容易中招。

**应用**：

| 症状 | 第一反应（错） | 真相 |
| --- | --- | --- |
| `OutOfMemoryError: Java heap space` | 加 `-Xmx` | 栈里是 `DirectByteBuffer`——**堆外内存**，`-Xmx` 管不着 |
| `FileNotFoundException`（贴图） | mod 缺文件 | **资源包把命名空间覆盖成了空** |
| `ClassCastException` | 模组有缺陷 | 管理员手动执行了指令——日志不会告诉你这个 |

---

### 4. 不可分辨的混合（Indistinguishable Mixing）

**机制**：公平题与陷阱题**无规律交替**，且不预先声明哪题是哪题。

**为什么有效**：它测试的不是「你会不会解」，而是
**「你是否知道什么时候该怀疑自己的方法论」**。

**应用**：[混合套路版](../mc-crash/mixed.html)

> 这是本系列最 "反人类" 的一版：正确的策略在每一题都不同，
> 而你无法事先知道该用哪一个。

---

### 5. 递归的荒诞（Recursive Absurdity）

**机制**：让错误的原因指向一个**逻辑上自洽但现实中荒诞**的源头。

**为什么有效**：笑点来自「这确实可能发生」的不安感。

**应用**：[混沌版](../mc-crash/chaos.html)

> 比如 `NegativeArraySizeException: -1`，来自一个计算
> `size = blocksPlaced - blocksBroken` 的模组——
> 玩家拆的比放的还多。**数学上完全成立。**

---

### 6. 永不完成（The 87% Stall）

**机制**：进度条冲到 87% 后卡死，甚至**倒退**。

**为什么有效**：它激活的是「沉没成本」心理——
已经等了这么久，舍不得关掉。

**应用**：[假下载页面](../fake-download/index.html)

> 每一条进度条规律都对应现实中真实存在的恶劣设计：
> 速度虚标、缓存回滚、倒计时重置、验证码永远失败。

---

### 7. 系统性背叛（Systemic Betrayal）

**机制**：用户以为自己在操作 A，系统却回应 B；或者本该可靠的东西开始不靠谱。

**为什么有效**：控制感的丧失比单纯的困难更令人沮丧。

**应用**：[假控制台](../fake-console/index.html)

> TPS 会随时间**持续下降**；`stop` 指令会拒绝执行，除非你输三次。
> 你越努力维持秩序，秩序崩得越快。

---

## 三、护栏：恶意不得越界

反人类 ≠ 伤害。以下护栏**没有任何例外**：

### 3.1 健康护栏

- 任何闪烁 / 抖动效果 **必须先弹光敏性癫痫警告**（入口确认框已内置）
- 任何效果 **必须提供一键停止**（`AH.stopAll()` / `🧘 关闭猎奇动效` / 安静模式）
- 禁止加载即开始的全屏强闪
- 用户说不舒服时，**以用户为准**，不得争辩

### 3.2 隐私护栏

- **零网络请求**。打开 DevTools 的 Network 面板应该是空的。
- **零数据收集**。不写 `localStorage`（除非有充分理由并在文档中说明）。
- 不获取地理位置、摄像头、麦克风、剪贴板读取权限。

### 3.3 诚信护栏

- 所有生成内容必须带**明显的虚构特征**（猎奇类名、表情符号、中文吐槽）
- 禁止冒充真实服务（银行、官方下载站、政府网站）
- 每个页面**必须**有 `仅供娱乐` 的 `warnline`
- README 与 LICENSE 中必须保留免责声明

### 3.4 语言护栏

- 只允许轻度脱敏吐槽词：`f**k` / `sh*t` / `h*ll` / `d*mn` / `fudge` / `bloody` / `geez`
- 禁止真实脏话
- 禁止涉及地域、性别、性取向、种族、宗教、身体、外貌的歧视性内容

## 四、技术诚实原则

本项目最特别的一点：**玩笑可以荒诞，但技术细节必须正确。**

| 允许 | 禁止 |
| --- | --- |
| 编造一个不存在的模组，但它的包名、类名、栈帧结构必须符合 Java 规范 | 把 `StackOverflowError` 说成内存不足 |
| 编一个荒诞的崩溃故事，但异常类型与触发条件必须真的对应 | 写出在标准下不可能发生的调用序列 |
| 出一道人做不出来的数学题，但答案必须是对的 | 出题人自己算错了 |

> **如果玩笑在技术上错了，那它就不是玩笑，是 bug。**

同理，`C++ 看代码猜输出` 里所有涉及未定义行为的题目，
「正确答案」必须是**标准真的没规定**——不能是作者说了算。

## 五、尺度检查表

新增一处「恶意」设计前，请逐条自问：

1. ☐ 我能用一句话说明它测试什么吗？
2. ☐ 它的效果是**有意的**，而不是随机的吗？
3. ☐ 用户有一键逃脱的方式吗？
4. ☐ 它会让人**不适**吗（健康层面）？还是只让人**抓狂**（认知层面）？
5. ☐ 它的技术细节经得起懂行的人检验吗？
6. ☐ 如果受害者是**我自己**，我还会觉得好笑吗？

第 6 条是最终裁判。

---

## 六、一句话总结

> **我们嘲笑的是「人类读不懂自己的代码」这个现象，**
> **不是嘲笑某个具体的人读不懂代码。**

如果你的玩笑需要一个具体的受害者才能成立，那它不属于本项目。
